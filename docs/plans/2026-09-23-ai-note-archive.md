# AI 对话归档实施方案

## 用户流程

1. 已登录用户从侧边栏进入「AI 归档密钥」，给新密钥命名。密钥只在创建时显示一次，有效期 365 天，可随时撤销或重新生成；页面显示名称、创建/过期时间和末尾四位。
2. 用户把密钥和部署后的 HTTPS 归档接口地址交给仓库内的 Agent Skill。Skill 在本机保存多个具名连接；每次归档前列出连接，要求用户明确选一个。
3. Skill 从当前对话整理 Markdown 标题与正文，用户确认内容后调用接口。接口只接受新增笔记，不提供读、改、删能力。新笔记进入现有 `daily_record` + `summarize`，自动挂上「外部汇入」标签，随后可在小程序中使用既有查看、编辑、搜索、分享功能。

## 安全与兼容

- 密钥用 32 字节随机数生成，数据库仅存 SHA-256 摘要；HTTPS 请求通过 Authorization 头传递。限制标题/正文大小，错误响应不包含密钥。密钥泄露时用户可以立即撤销。
- 防滥用限频：每把密钥固定时间窗内每小时最多 10 篇、每 24 小时最多 50 篇，超限返回 429 与重试时间；计数存于密钥文档，防止有效密钥被脚本刷库（每篇归档还会触发一次向量索引任务）。用户输入只作字符串写入固定字段，查询条件均为服务端计算值，无注入面。
- 旧笔记的三个集合 `daily_record`、`summarize`、`dict_category` 禁止客户端直连；原有客户端操作迁往验证七天登录凭证的云函数。游客仍可读取公共示例笔记及公共标签，分享链接继续通过独立分享接口读取。存有笔记全文副本的 `ai_learn_logs` 与 `ai_task_queue` 同步锁定，AI 辅导日志读写收口到 `aiLogService` 云函数（可见性与笔记一致：本人或公共示例记录）。
- 发布顺序：先部署新密钥集合的私有权限，再部署云函数及更新版小程序，最后收紧三个旧集合的权限；否则旧客户端会暂时失去笔记读写能力。旧版本客户端在权限发布后需升级。
- 云函数 URL 化需要部署者在 uniCloud 控制台配置 HTTPS 地址。该地址不写死在 Skill 中，由用户关联连接时录入。

## 实施与验证

1. 服务端：笔记 CRUD 代理、密钥管理、HTTP 归档接口、数据库 schema、越权保护。
2. 小程序：笔记 API 迁移、密钥管理页与侧边栏入口。
3. 仓库内 Skill：SKILL.md、标准库 Python 工具、安装/关联说明。
4. 验证：Node 单测覆盖密钥和权限关键分支，Python 单测覆盖多连接选择与密钥不泄漏；运行项目现有测试并检查 diff。
