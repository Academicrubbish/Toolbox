# AI 学习处理 Spec

## 背景

学习专区的核心价值在于 AI 对文档的智能处理。用户将学习内容导入并确认后，需要 AI 帮助进行归纳整理、生成练习题等学习辅助操作。

本子需求基于 Toolbox 已有的 AI 异步处理架构（定时触发器 + 任务队列），为学习专区提供 AI 处理能力。v1 阶段聚焦于"归纳复习"一个处理类型，确保跑通闭环后再逐步扩展。

## 目标

提供"归纳复习"AI 处理功能，基于用户确认的学习文档内容，生成精选笔记和针对性练习题。复用现有定时触发器 + 任务队列架构，保证处理过程不阻塞、不超时。

## 功能描述

### 用户故事

- 作为学生，我希望 AI 能帮我归纳笔记的核心知识点，生成一份精炼的复习笔记，以便高效复习
- 作为学生，我希望 AI 能根据我的笔记内容生成针对性练习题，以便检验学习效果
- 作为学生，我希望提交 AI 处理后不用一直等待，可以离开页面稍后回来查看结果

### 功能点列表

#### AI 处理选项

- v1 提供一种处理类型：**归纳复习**
- 归纳复习包含两个输出：
  - **精选笔记**：提炼文档核心知识点，生成结构化的复习笔记
  - **针对性练习题**：基于文档内容生成练习题（含答案和解析）
- 未来可扩展的处理类型（v2+）：
  - 预习扩展：对知识点进行延伸拓展，举一反三
  - 错题分析：分析错题笔记，定位错误根因
  - 知识盲区检测：对比知识框架，识别笔记中缺失的知识点

#### 异步处理架构

复用现有 AI 辅导的异步处理模式：

```
客户端                            云端
  │                                │
  │  提交 AI 处理请求 ──────────→  │  云函数（写入任务队列）
  │                                │    ├─ 更新 learn_document.status = 'processing'
  │                                │    ├─ 创建 learn_ai_result（status: pending）
  │                                │    └─ 写入 ai_task_queue（status: pending）
  │  ← 返回 taskId ──────────────  │
  │                                │
  │                    定时触发器 ──→  processLearnDocument 云函数
  │                                │    ├─ 取 pending 任务 → processing
  │                                │    ├─ 调用 GLM 文本模型（归纳复习 prompt）
  │                                │    ├─ 拆分结果为笔记 + 练习题
  │                                │    ├─ 更新 learn_ai_result → success
  │                                │    └─ 更新 learn_document.status = 'completed'
  │                                │
  │  查询处理结果 ──────────────→  │  客户端轮询查结果
```

#### Prompt 设计（归纳复习）

系统 prompt 核心要求：
- 输入：用户的 Markdown 格式学习文档
- 输出：结构化 Markdown，包含两部分
  - `## 一、精选笔记`：提炼核心知识点，使用标题层级组织，重要概念加粗
  - `## 二、针对性练习题`：生成 3-5 道练习题，每题包含题目、选项（如适用）、答案和解析
- 要求 AI 紧贴用户文档内容出题，不超出文档范围
- 输出格式使用固定分隔符，便于拆分

#### 结果展示

- AI 处理完成后，在文档详情页展示处理结果入口
- 结果页使用 towxml 渲染 Markdown 格式的精选笔记和练习题
- 支持下载结果为 Markdown 文件（复用 `utils/download.js`）
- 支持分享结果（复用现有分享功能）
- 处理失败时展示错误信息和重试按钮

#### 重新处理

- 用户修改文档内容后，可重新提交 AI 处理
- 重新处理会生成新的 `learn_ai_result` 记录，旧的保留但标记为 `superseded`
- 同一文档同一处理类型最多保留最近 3 次结果

### 用例

#### 用例 1：提交归纳复习

- **用例名称**：对学习文档进行归纳复习
- **前置条件**：用户已登录，在学习专区有一份 `confirmed` 状态的文档
- **操作步骤**：
  1. 用户进入文档详情页，点击"AI 学习处理"
  2. 展示处理选项列表（v1 仅"归纳复习"一项）
  3. 用户点击"归纳复习"
  4. 系统弹出确认弹窗："将对当前文档进行归纳复习，生成精选笔记和练习题，确认处理？"
  5. 用户确认后，系统保存文档（status: 'processing'）并提交 AI 任务
  6. 展示"处理中"状态，提示"AI 正在分析中，预计 1-2 分钟完成"
  7. 用户可离开页面
- **预期结果**：
  - 文档状态更新为 `processing`
  - `learn_ai_result` 创建一条 `pending` 记录
  - `ai_task_queue` 创建一条待处理任务

#### 用例 2：查看 AI 处理结果

- **用例名称**：查看归纳复习结果
- **前置条件**：文档的 AI 处理已完成（status: 'completed'）
- **操作步骤**：
  1. 用户进入文档详情页
  2. 看到"AI 处理结果"入口，显示处理类型和完成时间
  3. 点击进入结果页
  4. 结果页展示精选笔记和针对性练习题（Markdown 渲染）
  5. 用户可下载或分享结果
- **预期结果**：
  - 精选笔记和练习题正确渲染
  - 下载和分享功能正常

#### 用例 3：处理失败重试

- **用例名称**：AI 处理失败后重试
- **前置条件**：文档的 AI 处理失败（status: 'error'）
- **操作步骤**：
  1. 用户进入文档详情页
  2. 看到"处理失败"状态和错误信息
  3. 点击"重试"按钮
  4. 系统重新提交 AI 任务
- **预期结果**：
  - 新的 AI 任务进入队列
  - 原失败记录保留，新记录创建

## 边界条件

- **不处理空文档**：文档内容为空时不可提交 AI 处理
- **不处理超长文档**：文档超过 30,000 字符时提示"内容过长，请精简后再处理"（GLM token 限制）
- **防重复提交**：文档正在处理中（status: 'processing'）时不可重复提交
- **处理超时**：单次 AI 处理超过 120 秒视为失败（云函数超时限制）
- **API Key 安全**：GLM API Key 通过云函数环境变量传递，禁止暴露在客户端
- **结果上限**：同一文档同一处理类型最多保留最近 3 次结果
- **不可替代性**：本功能通过不可替代性检验——基于用户自己的文档内容生成个性化复习材料，通用 AI 对话产品无法直接替代

## 验收标准

- [ ] 文档详情页展示"AI 学习处理"入口
- [ ] v1 处理选项仅展示"归纳复习"
- [ ] 提交处理前有确认弹窗
- [ ] 提交后文档状态更新为 `processing`，展示处理中提示
- [ ] processing 状态下不可重复提交
- [ ] AI 处理完成后文档状态更新为 `completed`
- [ ] 精选笔记内容紧贴用户文档，不超出文档范围
- [ ] 练习题包含题目、答案和解析，数量为 3-5 道
- [ ] 结果页正确渲染 Markdown 格式内容
- [ ] 结果支持下载为 Markdown 文件
- [ ] 处理失败时展示错误信息和"重试"按钮
- [ ] 重试功能正常创建新的 AI 任务
- [ ] 修改文档内容后可重新提交处理，旧结果保留
- [ ] 同一处理类型最多保留最近 3 次结果
