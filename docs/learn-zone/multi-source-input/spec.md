# 文档新增多来源输入 Spec

## 背景

当前文档新增流程（`depart/form.vue`）中，用户添加总结内容只有一种方式：手动在 `md-editor` 中输入 Markdown。对于手写笔记用户和需要引用外部资料的用户来说，手动输入的门槛过高。

OCR 拍照识别和微信公众号链接解析是通用的内容输入能力，不应仅限于学习专区使用。将这两种能力集成到现有的文档新增流程中，让所有用户在任何场景下都能受益。

## 目标

在现有文档新增流程的"添加总结内容"环节，新增 OCR 拍照识别和微信公众号链接导入两种输入方式，与手动输入并列。用户选择 OCR 或链接导入后，系统自动识别/解析内容并填充到 `md-editor` 中，用户可编辑修正后保存。

## 功能描述

### 用户故事

- 作为学生，我希望在新增记录时能拍照上传手写笔记，系统自动识别为可编辑文本，以便省去手动输入的麻烦
- 作为学生，我希望在新增记录时能粘贴微信公众号文章链接，系统自动提取正文，以便快速导入网课资料
- 作为学生，我希望 OCR 识别和链接导入的内容能自动填入编辑器，我可以继续修改后再保存
- 作为学生，我希望保存记录后能直接选择 AI 辅导学习，以便对刚录入的内容进行智能处理

### 功能点列表

#### 输入方式选择

- 在 `depart/form.vue` 中，将"点击添加富文本总结"改为"添加总结内容"
- 点击后弹出输入方式选择弹窗（非新页面），展示三个选项：
  - **手动输入**：直接进入 `summarize/index.vue`（现有行为不变）
  - **拍照识别**：调用 `wx.chooseMedia` 选择/拍摄图片 → OCR 识别 → 结果填入编辑器
  - **导入链接**：弹出输入框粘贴链接 → 校验域名 → 解析 → 结果填入编辑器
- 如果已有总结内容，点击"查看/编辑总结内容"直接进入编辑器（现有行为不变）

#### OCR 拍照识别（depart 场景）

- 选择"拍照识别"后，调用 `wx.chooseMedia`（count: 9）
- 图片选择完成后，客户端逐张上传并展示进度，再进入整批识别 Loading
- 调用 `processOcr` 云函数，使用阿里云百炼 qwen3.6-flash 视觉模型并行识别
- 识别完成后，将 Markdown 内容预填充到 `summarize/index.vue` 的编辑器中
- 用户可在编辑器中修改识别结果
- 原始图片上传至云存储，记录在 `learn_ocr_log` 中（和学习专区共用同一集合）

#### 微信公众号链接导入（depart 场景）

- 选择"导入链接"后，弹出输入框让用户粘贴链接
- 校验链接域名为 `mp.weixin.qq.com`，非白名单域名提示"暂不支持该链接"
- 调用 `parseWechatArticle` 云函数解析文章
- 解析完成后，将标题和正文 Markdown 预填充到 `summarize/index.vue` 的编辑器中
- 文章标题自动回填到 `depart/form.vue` 的标题输入框（如果标题为空）

#### 保存后 AI 处理引导

- 记录提交成功后，在成功提示中新增引导："是否使用 AI 辅导学习？"
- 提供"立即辅导"和"稍后再说"两个选项
- 点击"立即辅导"跳转到现有的 AI 辅导流程（复用 `generateLearnNote`）
- 点击"稍后再说"返回列表页（现有行为）

### 用例

#### 用例 1：通过 OCR 拍照新增记录

- **用例名称**：拍照识别后新建记录
- **前置条件**：用户已登录，在 `depart/form.vue` 页面
- **操作步骤**：
  1. 用户填写标题和选择标签
  2. 点击"添加总结内容"
  3. 在输入方式选择弹窗中选择"拍照识别"
  4. 选择/拍摄 3 张手写笔记图片
  5. 系统逐张展示上传进度，随后展示"正在识别 3 张图片（预计约24s）"
  6. 识别完成，自动进入 `summarize/index.vue`，编辑器中预填充识别结果
  7. 用户修正个别识别错误，补充缺失内容
  8. 点击"保存"，返回 form.vue
  9. form.vue 显示"查看/编辑总结内容"
  10. 点击"提交记录"，保存成功
  11. 弹出提示"记录保存成功！是否使用 AI 辅导学习？"
  12. 用户点击"稍后再说"
- **预期结果**：
  - 记录成功创建，关联总结内容
  - 总结内容为用户修正后的 OCR 识别结果
  - `learn_ocr_log` 中保留原始图片和识别记录

#### 用例 2：通过链接导入新增记录并 AI 辅导

- **用例名称**：链接导入后新建记录并直接 AI 辅导
- **前置条件**：用户已登录，在 `depart/form.vue` 页面
- **操作步骤**：
  1. 用户点击"添加总结内容"
  2. 选择"导入链接"，粘贴微信公众号文章链接
  3. 系统校验域名通过，解析文章
  4. 解析完成，自动进入编辑器，标题自动回填到 form.vue
  5. 用户确认内容无误，保存总结
  6. 返回 form.vue，提交记录
  7. 弹出"是否使用 AI 辅导学习？"
  8. 用户点击"立即辅导"
  9. 跳转到 AI 辅导流程
- **预期结果**：
  - 记录成功创建
  - AI 辅导任务正常提交

#### 用例 3：手动输入（现有流程不受影响）

- **用例名称**：手动输入新建记录
- **前置条件**：用户已登录，在 `depart/form.vue` 页面
- **操作步骤**：
  1. 用户点击"添加总结内容"
  2. 选择"手动输入"
  3. 直接进入 `summarize/index.vue`，编辑器为空
  4. 用户手动输入 Markdown 内容
  5. 保存总结，返回 form.vue，提交记录
- **预期结果**：
  - 流程与现有行为完全一致，无回归问题

## Loading 策略

OCR 和链接导入采用**同步 loading 模态框**方案，不做异步后台处理。原因：

1. 结果需要用户编辑确认后才能保存，异步反而导致流程割裂
2. 时间可控：链接解析通常为 5-15 秒；OCR 图片上传串行执行，模型识别使用并发请求，客户端提供 100 秒超时保护
3. 用户在等待期间需要明确进度信息，避免焦虑

### 具体方案

| 阶段 | Loading 文案 | 时长预估 |
|------|-------------|---------|
| 图片上传 | "正在上传第 X/N 张..."（逐张更新） | 取决于网络 |
| OCR 识别 | "正在识别 N 张图片（预计约Xs）" | UI 按 8s/张保守估算；云端并行识别 |
| 链接解析 | "正在解析文章（预计约15s）" | 5-15s |

- **模态框不可关闭**，防止中途退出导致状态不一致
- **客户端超时保护**：OCR 100 秒、链接 60 秒，超时自动失败并提示
- **失败后可重试或切换手动输入**

## 边界条件

- **现有流程不变**：手动输入路径的交互逻辑、数据流转与现有完全一致，不引入任何回归风险
- **输入方式弹窗仅新增时展示**：已有总结内容时，点击"查看/编辑总结内容"直接进入编辑器，不弹窗
- **OCR/链接识别失败**：识别失败时提示错误信息，不进入编辑器，用户可重试或切换到手动输入
- **OCR 批次完整性**：任意图片识别失败或返回空内容时，整批标记为 `failed`，不把缺页内容静默带入编辑器
- **链接域名白名单**：仅支持 `mp.weixin.qq.com`，其他域名提示"暂不支持该链接，目前仅支持微信公众号文章"
- **图片数量上限**：单次最多 9 张（`wx.chooseMedia` 限制）
- **内容预填充不覆盖**：如果编辑器中已有内容（如用户从学习专区跳转），OCR/链接结果追加而非覆盖
- **AI 引导不强制**：保存后的 AI 引导是可选的，用户选择"稍后再说"不影响记录保存
