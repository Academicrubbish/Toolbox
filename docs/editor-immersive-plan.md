# 编辑器沉浸式改造 Plan

## Context

参考 `docs/proposal-d-final.html` 第 4 屏"编辑页 — 沉浸式全屏"，当前编辑器（summarize + md-editor）与设计稿差距较大。用户要求分析可行性并给出 Plan，重点关注重难点。

## 现状 vs 设计稿对比

| 维度 | 设计稿 | 当前实现 | 差距 |
|------|--------|---------|------|
| 导航栏右侧 | 自动保存状态 + "完成"按钮 + ⋮ 更多 | 仅有标题 + 返回 | 需改造 |
| 页面内容 | 标题输入 + 标签选择 + 正文一体化 | 仅正文 textarea | 差距大 |
| 工具栏 | 底部 8 个按钮（B I U \<\/\> H1 H2 图片 链接），毛玻璃 | 顶部 25 个按钮，3 行 | 需精简+移位 |
| 编辑体验 | 类 Notion 所见即所得 | 纯 textarea + 手动切换预览 | 差距极大 |

## 重难点分析

### 🔴 难点 1：富文本所见即所得 — 不可行

设计稿展示的是类似 Notion 的 block 编辑器（标题、正文、代码块视觉区分）。

**微信小程序的根本限制**：
- 没有 `contenteditable`，没有 `document.execCommand`
- `<textarea>` 是唯一可靠的文本输入方式，且样式不可定制
- 无法在 textarea 内实现不同段落不同样式

**结论**：纯文本 textarea + Markdown 语法标记是目前小程序的唯一可行方案。设计稿中的 block 编辑体验**无法实现**。

### 🟡 难点 2：标题+标签整合到编辑器 — 流程变更大

设计稿中编辑器内包含标题输入和标签选择。当前流程是：
1. 编辑器只管内容 → 返回 home
2. create-sheet Phase 2 填标题+标签 → 提交

如果把标题+标签移入编辑器，需要重构新建流程的数据传递。

**可行但需谨慎**：涉及 `summarize/index.vue`、`home/index.vue`、`create-sheet` 三个文件的数据流改造。

### 🟢 难点 3：工具栏精简 + 移到底部 — 可行

25 个按钮 → 精简为常用 8 个，其余收入 "⋮" 更多菜单。工具栏从顶部移到底部，毛玻璃效果。这是最 straightforward 的改动。

### 🟢 难点 4：导航栏改造 — 可行

右侧加入自动保存状态指示 + "完成"按钮 + 更多操作（上传 MD、清空等）。利用 nav-bar 已有的 `#right` slot。

## 推荐方案（只做可行的）

分两期：

### 第一期：工具栏 + 导航栏改造（改动小，收益高）

**涉及文件**：
- `component/md-editor/index.vue` — 工具栏精简+移到底部
- `component/md-editor/toolbar-actions.js` — 操作分组
- `subpackage/summarize/index.vue` — 导航栏右侧 slot

**具体改动**：

1. **工具栏从顶部移到底部，毛玻璃背景**
   - 常驻 8 个按钮：粗体、斜体、标题、链接、图片、代码、列表、预览切换
   - "⋮" 更多菜单收入不常用操作（上标、下标、缩进、表格、LaTeX、YUML、ECharts、清空、上传）
   - 保存按钮从工具栏移到导航栏右侧

2. **导航栏右侧改造**
   - "完成"按钮（保存）
   - "⋮" 更多菜单（上传 MD 文件、清空内容）

3. **编辑区自动聚焦，占满剩余空间**
   - 去掉工具栏占用顶部的空间，编辑区从导航栏下方开始
   - 底部工具栏 `position: fixed` 浮动，编辑区 `padding-bottom` 留出空间

### 第二期：标题+标签内联（可选，流程变更）

把标题输入和标签选择移入编辑器页面，简化新建流程。这需要重构数据流，建议作为独立任务。

## 验证方式

1. 编译后在微信开发者工具中打开编辑器页面
2. 验证工具栏在底部显示，8 个常用按钮 + 更多菜单
3. 验证导航栏右侧有"完成"按钮
4. 验证编辑区从导航栏下方延伸到底部工具栏上方
5. 验证所有原有操作（粗体、代码、LaTeX 等）仍可正常使用
